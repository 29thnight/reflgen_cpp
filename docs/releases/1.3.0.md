# reflgen 1.3.0

This release extends native runtime reflection so game-engine bindings can navigate
the complete reflected value graph and pass existing native objects to methods
without manufacturing process addresses from JSON.

## Runtime values and method calls

- Recursive descriptors cover record fields, inherited methods, containers,
  optional/expected/variant values, and explicitly adapted ownership wrappers.
- Borrowed getter results retain their owner and any materialized string/span
  arguments. Readonly access remains readonly through nested fields and pointer
  dereference.
- `method_info::invoke_bound` mixes serialized values with caller-resolved native
  `value_view` arguments. It validates receiver and argument types, constness,
  argument count, signature eligibility, and JSON placeholders before invoking.
- A bound call returns a request-scoped result plus materialized output arguments.
  Native argument slots are not inspected after execution because the call may
  have removed the object or invalidated its storage.
- `reflgen::script_once` excludes consuming methods from replayable getter paths
  while retaining their one-shot invocation APIs.
- Large method catalogs no longer recursively copy nested descriptor tuples,
  removing the MSVC nesting failure encountered with Scene-sized schemas.
- Incomplete reference results are guarded before assignment traits are queried.

These are runtime-only facilities. Existing authoring serialization schemas and
the generated reflection format remain unchanged. The library keeps its C++20
baseline; `std::expected` support follows the consumer's standard-library support.

## Lifetime boundary

The binding host resolves and pins native owners, applies its generation and
logical-destruction rules, and confines native result views to the operation.
Keeping argument storage alive does not make an invalidated container element or
deleted child object valid. No native address is accepted from serialized input.
Consuming ownership transfers, unrestricted callbacks, arbitrary memory ranges,
and internally reserved lifecycle methods still require an explicit host API.

See [runtime value bindings](../runtime-value-bindings.md) for contracts and
examples. CreatorEngine's full Editor/Player, graphics, and audio acceptance is
separate from this library's verification.

## Packages and verification

The release bundle is assembled only after the MSVC/clang-cl C++20/C++23 matrix,
IFC Debug/Release, PrSM ABI/bridge, Visual Studio extension, and package-consumer
jobs succeed. The Windows ZIP, NuGet package, and VSIX are copied from that run
without rebuilding. The published notes include the exact source commit, run URL,
and SHA-256 checksums.
