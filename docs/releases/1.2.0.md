# reflgen 1.2.0

This feature release adds direct F# consumption of native function-pointer tables.
It addresses the ABI-generation work needed for an executable-hosted engine such
as CreatorEngine to replace its C# binding layer with F# code.

## Direct native-table bindings

- Select an ABI with a `reflgen::table` type alias and generate it with
  `--fsharp-table`. The native C++ version constant is evaluated by the frontend.
- Generate F# value types for reachable nested records and fixed inline arrays,
  exact-width scalars, opaque pointers, and native function-pointer signatures.
- Bind a host-supplied pointer using its readable byte count and native ABI
  fingerprint. Check version, size, layouts, function signatures and required
  slots before creating cached typed delegates.
- Generate a C++ proof that catches stale declarations at native compile time,
  a fingerprint entry point, and a JSON contract for inspection.
- Preserve callback lifetime through explicitly rooted delegates. Native callback
  revocation and draining must precede disposal; engine handles retain their
  existing generation and instance semantics.
- Wire the outputs into CMake (`FSHARP_TABLE`, `FSHARP_NAMESPACE`) and MSBuild
  (`ReflgenFSharpTable`, `ReflgenFSharpNamespace`), including output ownership,
  incremental generation, input-collision protection and cleanup.

[CreatorEngine assessment, API examples, supported shapes and integration steps](https://github.com/29thnight/reflgen_cpp/blob/v1.2.0/docs/creatorengine-fsharp-abi.md).

## Integrated development work

This release also brings the existing development branches together without
rewriting their history:

- F# P/Invoke generation for explicitly selected C ABI methods, UTF-8 helpers,
  POD layout validation, synchronous callbacks and explicit ownership helpers.
- PrSM production binding IR, ABI catalogs and C bridges, including value records,
  enumerations, entity/component receiver policies and independently checked
  SHA-256 contract vectors.
- IFC engine reflection for public inheritance through CRTP helpers, friend
  access, nested types, overloaded methods and registration dependencies.
  Generated module-interface output is retained. Unverifiable imported template
  ancestry and partial-specialization cases fail before publishing an output.
- Runtime descriptors no longer offer a heap factory for types that explicitly
  forbid heap allocation.

The existing C++20 reflection API, generated reflection format 2 and serialization
wire format are retained. Regenerate optional binding outputs with the tools and
headers from this release.

## Validation and scope

The release pipeline requires the MSVC/clang-cl C++20/C++23 matrix, IFC Debug and
Release tests, PrSM contract and bridge tests, Visual Studio extension tests, and
package consumers to succeed before assembling the release bundle. The bundle
contains the unchanged Windows ZIP, NuGet package and VSIX from that same run,
with checked package identities, source provenance and SHA-256 sums.

The direct F# executable calls a real C++ provider using generated bindings and
references only .NET/FSharp.Core assemblies. Its modeled CreatorEngine boundary
covers aggregate arguments/results, nested physics and asset values, counted
buffers, inline arrays, stale handle/instance behavior, reverse callbacks across
GC and ABI rejection paths. Existing C/C#/F# method consumers remain regression
gates. Generated IFC module output is compiled and executed as a consumer.

This is a generator release. CreatorEngine's full 205-entry table, hostfxr
bootstrap, public managed API, collectible loader, Editor/Player execution and
performance acceptance still require the engine integration described in the
guide. It does not claim that the engine's C# projects have already been removed.
The earlier 1.1.0 live Visual Studio UI verification remains a historical record;
this release's automated VSIX build/tests do not imply a new manual IDE session.
